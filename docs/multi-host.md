# Agent 纳管与按主机授权

iptables-web 采用中心端 + 轻量 Agent 模型。只有中心端提供 Web 页面、登录、用户、主机清单和权限分配；每台被管 Linux 主机只运行独立的 `iptables-web-agent` 二进制，在本机执行固定范围的防火墙操作。

```text
目标机 Agent ──签名申请──► 中心端待确认队列
                              │ 管理员单台或批量确认
                              ▼
浏览器 ──► 中心端 ──HTTP(S) + 独立凭据──► Agent ──► 本机 iptables
```

中心端不使用 SSH。Agent 没有页面、用户、登录会话、主机清单、访问密钥管理或任意 URL 代理。规则、审计和回滚数据保存在规则实际生效的目标主机上。

## 安装与主动申请

发布包同时包含中心端和 Agent 二进制。把发布包复制到目标机并进入解压目录后，指定中心地址运行：

```bash
sudo MANAGER_URL=http://10.0.0.5:33801 bash install-agent.sh
```

也可在终端中交互安装，脚本会询问管理端地址、显示名称、分组、回连地址、后端和可选 CA：

```bash
sudo bash install-agent.sh
```

直接在终端执行且未设置 `MANAGER_URL` 时会自动进入交互模式，不要求 `--interactive`。该参数仅用于明确强制交互。CI、云初始化等非终端环境不会等待输入；应设置 `MANAGER_URL`，或使用 `--non-interactive` 明确要求只读取环境变量。

可同时指定显示名称、分组和中心可回连端口。`MANAGER_URL` 应使用中心内网 IP；浏览器前的 HTTPS 反向代理不能代替 Agent 的来源 IP 注册链路：

```bash
sudo MANAGER_URL=http://10.0.0.5:33801 \
  MANAGER_CA_FILE=/etc/pki/manager-ca.pem \
  AGENT_NAME=prod-node-01 AGENT_GROUP=production \
  AGENT_PUBLIC_URL=http://10.0.0.21:33802 \
  bash install-agent.sh
```

安装器只部署一个预编译二进制、私有目录和 systemd 服务，默认监听 `0.0.0.0:33802`，不要求 Go，也不修改 firewalld、安全组或其他网络策略。Agent 启动后立即向 `MANAGER_URL` 发送签名申请，此后每 15 秒重试；管理员无需在中心手工填写地址或密钥。

管理端“Agent 纳管”页会显示待确认队列。管理员可单台确认、勾选后批量确认或拒绝。确认时中心会使用 Agent 自动交换的独立凭据回连受保护的 `/api/v1/system/status`；只有认证和状态检查都成功才加入主机清单。重名主机会自动追加 Agent ID 前缀，之后可编辑显示名称、分组和启停状态。

批准后 Agent 仍每 15 秒发送一次签名请求作为心跳，页面以同样周期刷新心跳视图。纳管概览和 Agent 清单对每台主机的受保护回连探测限频为每分钟至多一次：超过 45 秒未上报显示“Agent 离线”；仍在上报但中心无法访问其管理接口显示“回连异常”；探测成功显示在线与延迟。最近上报时间和最近回连检测时间分别展示，便于区分 Agent 进程停止、网络回程阻断和凭据/证书问题。

申请中的回连主机部分会被中心固定为该请求的实际来源 IP，仅保留 Agent 声明的协议和端口，不能借公开申请入口要求中心访问任意地址。多网卡或 NAT 环境下应确保中心确实能访问这个来源 IP 和 Agent 端口，否则审批会保留为失败状态供重试。当前纳管仍要求中心可以主动回连 Agent，不是跨 NAT 长连接。

## 身份与凭据

Agent 首次启动生成稳定的 Ed25519 身份，私钥种子保存在 `/etc/iptables-web-agent/agent.identity`，权限 `0600`。申请包含时间戳、随机 nonce 和签名；Agent ID 由公钥摘要生成。Agent 与中心时钟必须相差不超过 5 分钟，建议启用 chrony 或 systemd-timesyncd。

Agent 的管理凭据由进程自动生成和交换：

- 目标机磁盘只保存 `/etc/iptables-web-agent/agent.key.sha256`，权限 `0600`；
- 中心仅在待确认内存中短暂持有明文，批准后以 AES-GCM 加密写入 `hosts.json`；
- 待确认列表、主机列表、日志和审计都不返回明文、密文或 Agent 公钥；
- 待确认队列不写盘，中心重启后 Agent 会自动重新申请；待确认项超过 10 分钟未刷新会过期；
- 拒绝的身份在当前中心隐藏 24 小时，Agent 本身不会被卸载或改规则。

若明确需要轮换 Agent 凭据，在原发布包目录重新运行安装器：

```bash
sudo MANAGER_URL=http://10.0.0.5:33801 ROTATE_AGENT_KEY=true bash install-agent.sh
```

同一签名身份、同一回连地址可以自动恢复或轮换凭据；地址改变仍需管理员重新确认。不要删除 `agent.identity`，否则中心会把它视为一台新 Agent。

## HTTP 与 HTTPS

每台 Agent 的连接协议独立：

- HTTP 只适合可信且隔离的内网；自动交换凭据会经过网络，应通过防火墙、VLAN、VPN 或安全组把 `33802` 限制为仅中心端 IP 可访问。
- HTTPS 适合不可信网络。当前 Agent 自身监听 HTTP，可在 Agent 前部署 HTTPS 反向代理；中心始终按申请来源 IP 回连并验证证书，所以证书必须包含该内网 IP 的 IP SAN。使用私有 CA 时，可在待确认行展开“私有 CA”并在首次审批时粘贴 PEM；后续同地址密钥轮换会复用该 CA。
- Agent 访问 HTTPS 中心时可通过 `MANAGER_CA_FILE` 指定中心私有 CA；安装器会把它复制为 `/etc/iptables-web-agent/manager-ca.pem`。HTTP 重定向不会被跟随。

## 页面与用户权限

页面没有全局“切换主机”选择器。用户先进入“纳管概览”；每台可访问主机逐行显示名称、分组、地址和连接状态并默认收起，展开后按需加载规则摘要，再进入该主机的概览、规则、实时链、Docker、备份与审计页面。规则助手属于不执行命令的全局工具，固定放在侧栏，不再重复出现在每台主机内部。

中心服务器自身算作一台内置纳管主机，但不伪装成远程 Agent。它使用保留 ID `local`，可从纳管概览中的本机行或侧栏“本机防火墙”进入同一组管理页面，并计入纳管总数和在线数。管理员始终可访问；普通用户只有被明确逐台授予 `local` 后才看到入口并拥有完整本机防火墙能力，本机不通过主机组隐式继承。

- 管理员自动拥有全部远程主机和中心本机，可确认申请、命名、分组、停用和移除 Agent，也可创建用户并按本机、单台远程主机或主机组分配权限。
- 普通用户只能看到逐台分配或授权主机组覆盖的主机，但对这些主机拥有完整的规则、实时链、Docker、备份、恢复、审计和回滚权限。
- 普通用户不能审批 Agent、修改其他用户、分配权限或管理中心凭据。
- 主机组按名称动态继承：以后加入已授权组的远程主机会自动可见；本机和未分组主机只能逐台分配。
- 直接请求未分配远程主机 ID 返回 `404`，未获 `local` 授权的本机请求返回 `403`；修改用户逐台或主机组分配会立即刷新现有会话。

服务器是权限边界，界面隐藏按钮不是授权依据。`POST /hosts` 不接受手工注册，主机地址也不能通过 `PUT /hosts/{id}` 任意改变；地址变更必须来自相同 Agent 身份的签名申请。

## 固定远程接口

中心仅允许转发规则、链、Docker、备份、恢复、审计和回滚接口。不得增加用户、认证、中心主机清单、访问密钥或任意 URL 转发。批量创建规则最多包含 100 台主机，最多并发 5 个请求，并逐台返回结果；它不是跨主机事务。

## 安全卸载 Agent

默认停止服务，逐条删除 `rules.json` 中带 `iptables-web:<rule-id>` 所有权注释的 Agent 规则，再删除二进制、身份、配置和数据：

```bash
sudo bash uninstall-agent.sh
```

可用选项：

```bash
sudo bash uninstall-agent.sh --keep-rules   # 保留当前运行规则
sudo bash uninstall-agent.sh --keep-data    # 保留身份、哈希和数据
sudo bash uninstall-agent.sh --purge --yes  # 无交互完整清理
```

卸载器从不 flush 链，也不删除无所有权注释的相似规则、Docker/firewalld 规则或管理员规则。精确清理失败时默认保留 Agent 与数据，只有明确接受残留时才使用 `--force`。普通服务重启不会清理规则。

## 当前边界

Agent 会主动发起纳管申请，但批准后的管理流量仍由中心回连 Agent。跨 NAT 长连接、内建 TLS、mTLS、只读角色、策略版本和跨主机事务尚未实现。
